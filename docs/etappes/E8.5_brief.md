## What this etappe does

Closes the §4.3 write-back lifecycle. After E8.5, an operator running `theogony serve` has a long-lived `OneirosWorker` reading EPHEMERA + MNEME every 60 s (configurable), recomputing connectivity / freshness / vitality, promoting nodes that cross `vitality ≥ 0.7`, and degrading stale `vitality ≤ 0.25 ∧ idle ≥ 7d` MNEME nodes back to EPHEMERA. Every tick emits one `OneirosTickReport` to `data/run_reports/oneiros/`.

The Plan §1 demonstration moment was already closed by E9 — E8.5 makes the Chronik *live*. With E8.5 in main, a fresh ingest's nodes don't just sit at their initial scores forever; the Memory layer breathes.

## Scope decisions (read first)

### PHX-0048 reopened — `batch_update_scores` shape lands in this etappe

Daedalus's E8.5 design Q5 verdict: drop the original single-node Cypher COALESCE shape (which couples vitality formula to Cypher and frustrates PHX-0009), replace with a bulk `batch_update_scores(updates: Sequence[ScoreUpdate])` where vitality is **precomputed client-side** in the worker and Cypher only stores the number. This shape:

- Collapses per-tick write cost from O(N) round-trips to one.
- Preserves PHX-0009's freedom to evolve the vitality formula (Cypher is formula-agnostic).
- Reduces the `RelevanceTracker.bump`-vs-worker race to "one tick of staleness on the post-bump vitality recompute" (the bulk update touches `connectivity / freshness / vitality` but **not** `relevance`, so a concurrent bump's relevance write survives).

PHX-0048 (`phoenix-backlog/PHX-0048.yaml`) is the source of truth for the Cypher and acceptance criteria. Treat it as the second deliverable of this PR, not a follow-up.

### `count_neighbors_in_layer` is the second new Protocol method

Step 2 of `_tick()` needs a bulk node-id → degree map for one layer in one round-trip. Add to `KnowledgeStore` Protocol:

```python
async def count_neighbors_in_layer(self, layer: Layer) -> dict[str, int]: ...
```

`InMemoryKnowledgeStore` iterates `self._edges` and counts. `Neo4jKnowledgeStore` uses one Cypher (range index on `:KnowledgeNode(layer)` plus relationship projection):

```cypher
MATCH (n:KnowledgeNode {layer: $layer})
OPTIONAL MATCH (n)-[r:RELATION]-()
RETURN n.id AS id, count(r) AS degree
```

The `OPTIONAL MATCH` ensures isolated nodes (degree 0) appear in the result; the undirected `-[r:RELATION]-` matches both incoming and outgoing edges (the worker's connectivity score is symmetric per Plan §5 E8.5).

### `OneirosTickReport` is already wired

`reporting/models.py` already carries `OneirosTickReport` and `VitalityShift` (E2/E5 deliverables). `Settings.report.oneiros_tick_retention=100` is already wired and `RunReportWriter` already enforces caps. The worker just builds the report and calls `writer.write(report)` — no plumbing changes needed.

## Classes & APIs

The Plan §5 E8.5 block is the spec-of-record. This section is the **interface contract** — Talos confirms each shape in the PR body.

### `OneirosWorker` — `src/theogony/memory/oneiros.py`

```python
class OneirosWorker:
    """Long-running asyncio task owning the §4.3 write-back lifecycle.

    Lifespan: instantiated in api/app.py:lifespan (E9 wired the slot;
    E8.5 fills it). `await worker.run()` runs until cancelled by the
    lifespan's shutdown ordering (Plan §4.4 5-s budget).

    See Plan §5 E8.5 for the full _tick() spec.
    """

    def __init__(
        self,
        store: KnowledgeStore,
        settings: Settings,
        report_writer: RunReportWriter,
        *,
        tick_interval_s: float | None = None,
    ) -> None:
        self._store = store
        self._settings = settings
        self._writer = report_writer
        self._tick_interval_s = tick_interval_s if tick_interval_s is not None else settings.oneiros.tick_interval_s

    async def run(self) -> None: ...    # main loop, per Plan §5 E8.5 pseudo-code
    async def _tick(self) -> None: ...  # per Plan §5 E8.5 pseudo-code
    def _finalize_report(self, ...) -> OneirosTickReport: ...
```

`tick_interval_s=None` falls back to `Settings.oneiros.tick_interval_s` (Q1). Tests pass `tick_interval_s=0.1` directly; production reads from Settings.

### `ScoreUpdate` — `src/theogony/core/model.py`

Place next to `NodeScores`. Keep the worker-friendly partial-update shape from PHX-0048:

```python
class ScoreUpdate(BaseModel):
    node_id: str = Field(min_length=1)
    confidence: float | None = Field(default=None, ge=0.0, le=1.0)
    relevance: float | None = Field(default=None, ge=0.0, le=1.0)
    connectivity: float | None = Field(default=None, ge=0.0, le=1.0)
    freshness: float | None = Field(default=None, ge=0.0, le=1.0)
    vitality: float | None = Field(default=None, ge=0.0, le=1.0)  # precomputed by caller
```

The worker only ever writes `(connectivity, freshness, vitality)` — `confidence` and `relevance` stay `None` from the worker's calls. Both fields exist in the model so `RelevanceTracker.bump` (or a future caller) can use `batch_update_scores` for its own use case if it wants.

### `KnowledgeStore` Protocol additions — `src/theogony/core/store.py`

```python
class KnowledgeStore(Protocol):
    ...

    async def count_neighbors_in_layer(self, layer: Layer) -> dict[str, int]:
        """Map node-id → degree (in + out edges) for all nodes in `layer`.

        Used by OneirosWorker._tick() (Plan §5 E8.5 step 2) to compute
        connectivity in one round-trip per layer instead of N
        get_neighborhood calls.

        Isolated nodes appear with degree=0. Cross-layer edges count
        toward the in-layer node's degree (an EPHEMERA node connected
        to a MNEME node has degree 1 in the EPHEMERA result).
        """
        ...

    async def batch_update_scores(self, updates: Sequence[ScoreUpdate]) -> None:
        """Bulk write of partial score updates (PHX-0048 reopen).

        Per row, only non-None fields are written; other fields keep
        their existing values. Atomic at the bulk level (one Cypher
        transaction); single-node concurrent writes (RelevanceTracker.bump)
        interleave at single-node granularity per Plan §5 E8.5
        Race-condition note (Q5).

        Empty `updates` is a no-op (no round-trip).

        Missing node-ids (deleted between snapshot and write) are
        silently skipped per Plan §5 E8.5 concurrency table row 5.
        """
        ...
```

The existing per-node `update_scores(node_id, scores: dict[str, float])` stays — `RelevanceTracker.bump` keeps using it (single-node reactive use case is the right shape there).

### `batch_update_scores` — Neo4j Cypher

Per PHX-0048 description (verbatim, the ticket is the source of truth):

```cypher
UNWIND $rows AS r
MATCH (n:KnowledgeNode {id: r.node_id})
SET n.confidence   = COALESCE(r.confidence,   n.confidence),
    n.relevance    = COALESCE(r.relevance,    n.relevance),
    n.connectivity = COALESCE(r.connectivity, n.connectivity),
    n.freshness    = COALESCE(r.freshness,    n.freshness),
    n.vitality     = COALESCE(r.vitality,     n.vitality)
```

PROFILE confirms one MATCH per row using the existing `:KnowledgeNode(id)` range index. Microbenchmark target ≥20× speedup vs N per-node `update_scores` (PHX-0048 acceptance); reject if <5×.

## Plan deviations to escalate (not anticipated, but if encountered)

- **`count_neighbors_in_layer` Cypher cost on a corpus where some nodes have huge fan-out.** If PROFILE shows db-hits >200 on the 2000-node demo target, escalate via a PR comment + a fresh PHX ticket. Do NOT rewrite the Cypher creatively; the simple shape is the right starting point.
- **`asyncio.sleep` monkeypatch flakiness on Python 3.13.** If Idiom-A misbehaves under 3.13's asyncio refactor (unlikely but possible), document in the PR body and fall back to a `time.monotonic()`-based mock with a longer manual yield budget. Do NOT pull in a time-travel plugin.
- **`testcontainers` integration test exceeds 30 s wall-clock** on a slow CI runner. If so, lower the tick count from 4 to 2 and document the trade-off; do NOT remove the integration test entirely.
- **`MultiHopBreakdown` Optional schema change breaks existing reports on disk.** If Pydantic raises on read, the migration path is different than expected — escalate via a PR comment + a quick decision: either ship a one-shot migration script, or accept the historical reports as un-readable post-E8.5 (documented). Hesiod's expectation: Optional + default=None lets existing reports parse fine, but verify with one round-trip test against an actual on-disk report (`pytest tests/test_reporting_models.py::test_legacy_report_parses` if you want to add it).
- **`batch_update_scores` microbenchmark fails the ≥5× reject threshold.** Same shape as PHX-0046's threshold deviation: if the empirical Mac/testcontainers number is hardware-bound (server-side index-update cost), document it in the PR body, lower the assert threshold, and file a sibling to PHX-0054 (bare-metal re-measurement). The Cypher correctness in collapsing round-trips is the contract; the wall-clock multiplier is hardware-dependent.
